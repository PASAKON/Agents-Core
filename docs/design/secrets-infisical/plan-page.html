ง. ชื่อโปรเจคและเครื่องใน Infisical

Org-Infra: กฎการเขียนและกฎการตั้งชื่อ

โปรเจคนี้เก็บ key ที่เปลี่ยนแปลงบัญชีได้ ถ้าหลุดจะพังทั้งระบบ กฎจึงเข้มกว่าโปรเจคอื่น

อะไรเข้า อะไรไม่เข้า

  • เข้า: DNS (Cloudflare), deploy และตั้งค่าโปรเจค (Vercel), สิทธิ์ admin ของ repo (GitHub), การเพิ่มเครื่องเข้า Tailscale, Postgres superuser และช่องทางที่ Infisical ใช้ส่งค่าไป Vercel
  • ไม่เข้า: key ที่บริการต้องใช้ตอนรัน ให้ไปอยู่โปรเจคของบริการนั้น เช่น R2 อยู่กับ ClaudeFlow, Drive อยู่กับ Agents-Core
  • ไม่เข้า: key ที่เป็นตัวเครื่องเอง (SSH key, Tailscale ของเครื่อง, deploy key) ให้อยู่บนเครื่องนั้น Org-Infra เก็บแค่ลายนิ้วมือ (fingerprint) กับวันหมดอายุ ระบบจะได้เตือนได้
  • ใครอ่านได้: พี่กับ Mac เท่านั้น ถ้าจะเพิ่มเครื่องต้องให้พี่อนุมัติ ถ้า Contabo หรือ winbox ต้องใช้ ให้ส่งคำขอผ่าน Run Inbox แทนการอ่าน key เอง

กฎการเขียน

  1. พี่เป็นคนเดียวที่ใส่ค่า โดยใส่ในเว็บ Infisical และก๊อปจากหน้า provider ตรง ๆ CTO เตรียมชื่อ, metadata และขอบเขตให้ ส่วน agent ไม่มีวันได้เห็นค่า
  2. ขอบเขตแคบที่สุดที่ provider มีให้ เช่น 1 zone, 1 repo หรือ 1 โปรเจค ถ้าต้องกว้างกว่านั้นให้ติด tag wide พร้อมเขียนเหตุผล
  3. ต้องมีวันหมดอายุทุกตัว: admin ไม่เกิน 90 วัน ส่วน rw และ ro ไม่เกิน 1 ปี
  4. 1 key ต่อ 1 งานต่อ 1 เครื่อง ห้ามใช้ key เดียวกันสองเครื่อง ถ้าเครื่องหาย จะได้ลบเฉพาะ key ของเครื่องนั้น
  5. กรอก metadata ครบ และเพิ่มอีก 3 ช่อง: หลุดแล้วโจรทำอะไรได้ (blast_radius), ลิงก์หน้ายกเลิก key (revoke_url) และเครื่องกับ script ที่ใช้ (used_by)
  6. ทุกครั้งที่สร้าง เปลี่ยน หรือลบ ให้จดหนึ่งบรรทัดในทะเบียน key (แบบฟรีไม่เก็บประวัติ บรรทัดนี้จึงเป็นประวัติเดียวที่มี)
  7. เปลี่ยนไปข้างหน้าเท่านั้น: สร้าง key ใหม่ → ใส่ Infisical → ตรวจว่าใช้ได้ → แล้วค่อยลบ key เก่า
  8. ห้ามวางในแชท, ห้าม commit ลง git, ห้าม screenshot, ห้ามเก็บสำรองที่อื่น และห้ามใช้ key ทั้งบัญชีถ้ามีแบบแคบให้เลือก
  9. บัญชี Infisical ของพี่ต้องเปิด 2FA และ recovery code พี่เก็บเองแบบ offline ห้ามเก็บใน Infisical ใน repo หรือในแชท

  3. P2นำร่องที่ LineAutomationCTO · import จากไฟล์บนเครื่องเองตรง ๆ, restart ให้ดึงจาก Infisical แล้วลบ .env
  4. P3ย้ายทีละโปรเจคCTO · ลบ .env ของแต่ละโปรเจคหลังรันจาก Infisical ได้ปกติครบ 7 วัน ส่วน Archive ลบหลังพี่ OK (#177)
  5. P4เปลี่ยน key ที่หลุด 7 ตัว + แยก key ที่ใช้ร่วมกัน ตั้งชื่อตามกฎใหม่พี่ login ผ่าน relay บนมือถือ + CTO
  6. P5ระบบเตือนวันหมดอายุCTO · สร้างหน้าทะเบียน key อัตโนมัติ และแก้ IRON §34 ให้ชี้มาที่ Infisical
  7. P6เปลี่ยนชื่อตัวแปรให้ตรงกฎ ข.CTO/DEV · ทำเป็น PR ทีละโปรเจค

ที่ยังไม่ได้ยืนยัน

  • ตัวพี่เอง (คน) นับเป็น 1 ใน 5 identity ของแบบฟรีด้วยหรือเปล่า แผนนี้คิดไว้ก่อนว่านับ
  • แบบฟรีสร้างโปรเจคได้กี่อัน หน้าราคาไม่ได้เขียนไว้
  • การเตือนให้เปลี่ยน key ใน Infisical ต้องใช้แพ็กเกจไหน (แต่ระบบเตือนของเราทำงานได้โดยไม่ต้องพึ่งอันนี้)
  • Supabase, Gemini AI Studio และ R2 มีช่องตั้งชื่อ key หรือเปล่า และความยาวสูงสุดของ provider ส่วนใหญ่ (มีแค่ GitHub ที่เขียนไว้ว่า 40)
