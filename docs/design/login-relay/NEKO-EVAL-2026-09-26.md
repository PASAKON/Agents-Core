## 1. What neko is, and what it replaces

[m1k1o/neko](https://github.com/m1k1o/neko): a **real headed Chrome** (Xorg + GStreamer, not
`--headless`) in a Docker container, streamed over **WebRTC** to a web client; the person clicks and
types on the real page. 22.4k stars, Apache-2.0, v3.1.5 (2026-08-05), commits on 2026-09-24
(OIDC-only auth). v3 is the current line ([release notes](https://neko.m1k1o.net/docs/v3/release-notes)).

It replaces the relay's screencast, mirror, direct-touch and success-guessing. It does not replace:
the Browser Home idea (one profile per account), the pill list, Run Inbox, the CDP workers, or the
post-login automation (`scripts/infisical/watch_login.sh` pattern). The industry does the same
split — Cloudflare Browser Run "structured handoff", Browserless "hybrid automation": the **human
presses Done**, the system never guesses
([Cloudflare HITL](https://developers.cloudflare.com/browser-run/features/human-in-the-loop/),
[Browserless](https://docs.browserless.io/baas/monitor-sessions/hybrid-automation)).

## 2. Facts that matter for us

| Topic | Fact | Source |
|---|---|---|
| Transport | WebRTC (Pion). UDP port range `NEKO_WEBRTC_EPR` or a single mux port `NEKO_WEBRTC_UDPMUX`/`TCPMUX`; `NAT1TO1` = the one IP clients reach; ICE lite for a directly reachable server; TURN only when no direct path | [webrtc config](https://neko.m1k1o.net/docs/v3/configuration/webrtc) |
| Reverse proxy | only the HTTP/WS port (8080) can be proxied; media never goes through nginx/Caddy/Cloudflare (open issue #393) | [reverse proxy](https://neko.m1k1o.net/docs/v3/reverse-proxy-setup), [#393](https://github.com/m1k1o/neko/issues/393) |
| **Our advantage** | `terminal.mooniex.com` already resolves to Contabo's tailnet IP (100.118.171.23); the iPhone is a tailnet node → `NAT1TO1=100.118.171.23`, one UDP mux port, **no public port, no TURN** (measured 2026-09-26: ufw allows only 22/80/443 publicly; `ts-input` precedes ufw) | this session |
| iPhone | touch works; virtual keyboard fixed in v3.0.5/v3.0.8 and via PRs #497/#522 after regressions (#115, #523); "Mobile support" #251 still open since 2023; pinch/zoom UNVERIFIED | [#251](https://github.com/m1k1o/neko/issues/251), [#115](https://github.com/m1k1o/neko/issues/115) |
| **CDP (our gap)** | no stock way to add `--remote-debugging-port`; issue #391 (Playwright over CDP) open since 2024; third-party forks patch the supervisord launch line → needs our own image or a mounted `/etc/neko/supervisord/chromium.conf` | [#391](https://github.com/m1k1o/neko/issues/391), [browsers](https://neko.m1k1o.net/docs/v3/customization/browsers) |
| Persistence | mount `/home/neko/.config/chromium`; the default Chromium policy clears cookies on shutdown → policy JSON must allow persistent data; host dir `chown 1000:1000`; stale `Singleton*` lock files after an unclean stop (#605) | [browsers](https://neko.m1k1o.net/docs/v3/customization/browsers), [#605](https://github.com/m1k1o/neko/issues/605) |
| API | REST + WebSocket, OpenAPI in the repo; sessions list/get/disconnect, connect/disconnect events, Request/Release/Take/Give control; auth by cookie, bearer or `?token=` | [API](https://neko.m1k1o.net/docs/v3/api) |
| Embed | iframe the stock client with `?embed=1` (no sidebar/topbar) or `?cast=1` (view only), `?usr=&pwd=` prefill; no official npm client | [UI](https://neko.m1k1o.net/docs/v3/customization/ui) |
| Many accounts | [neko-rooms](https://github.com/m1k1o/neko-rooms) runs one container per room with its own API — the Browser Home shape | |
| Security | DTLS-SRTP by design; password providers or OIDC (new); no IP allowlist → the tailnet is the allowlist; file transfer off with `NEKO_FILETRANSFER_ENABLED=false` | [plugins](https://neko.m1k1o.net/docs/v3/configuration/plugins) |
| Resources | no official RAM/CPU figure; Chromium images need `shm_size` ≥ 2 GB (docs) — Contabo has 7.8 GB total, ~2.8 GB free → one instance at a time until RAM grows | [troubleshooting](https://neko.m1k1o.net/docs/v3/troubleshooting) |
| Google block | no issue confirms or denies Google refusing sign-in inside neko; structurally a headed Chrome (the case Google admits), unlike the HeadlessChrome UA that got E_BLOCKED on contabo:9250 on 2026-09-24 | UNVERIFIED |

Alternatives looked at: linuxserver/docker-chromium (Selkies-based, 1:1 remote browser, no session
API), Kasm Community (5-session cap, heavier), selkies (engine only), Guacamole (needs a
VNC/RDP target). neko is the best fit for "phone logs in, agent continues".

## 3. Pilot (proposed, $0, tailnet-only, one container)

1. `Work/neko-pilot/` on Contabo: `ghcr.io/m1k1o/neko/chromium`, `shm_size 2g`, HTTP 8080 bound
   to 100.118.171.23 only, `NEKO_WEBRTC_UDPMUX=59000` + `TCPMUX=59000`, `NAT1TO1=100.118.171.23`,
   `ICELITE=1`, passwords from a root-only env file (never in git), profile volume
   (`chown 1000:1000`) + a policy JSON that keeps cookies, `NEKO_FILETRANSFER_ENABLED=false`.
   Stop the two headless homes (`relay-home.mjs quit`) during the test to free RAM.
2. CEO on the iPhone (tailnet on): open the page, log in to Google and Infisical for real.
   Measure: keyboard usable · Google blocked or not · latency · container RSS.
3. CDP: mount a `chromium.conf` override adding `--remote-debugging-port=9222` (in-container),
   publish `127.0.0.1:9222` on the host; prove `scripts/infisical/wait_login.mjs` and a worker can
   attach; re-check that Google still lets the login through with the port on.
4. All three pass → integrate: Browser Home = a neko room (neko-rooms API), the pill opens the
   `?embed=1` page inside the Console with a **เสร็จแล้ว** button that ends the hand-off, the
   worker gets the CDP URL. Keep the relay only for QR sites if neko cannot show a QR page (it can:
   it is the real page).
