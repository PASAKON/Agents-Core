# กฎเรื่อง key ชุดเดียว (HQSecurity M1) สรุปให้ CEO

รวมกฎเรื่อง key ทั้งหมดไว้ที่ skill เดียว `ALL_Rules_Secrets` และสคริปต์ KeyFetch จะไม่ยอมสร้าง key ถ้าไม่มีชื่อ ขอบเขตสิทธิ์ หรือวันหมดอายุ โดยเช็คก่อนกดสร้างที่หน้า provider

| ข้อ | สั้นๆ |
|---|---|
| 1 ที่เก็บ | อยู่ใน Infisical project ที่ชื่อเดียวกับ repo · Org-Infra คุณใส่เองคนเดียว · ห้ามสร้าง .env ใหม่ |
| 2 ชื่อ | ชื่อบนหน้า provider เช่น ag-core-prod-ro-exp2027-10-14 (ไม่เกิน 40 ตัว) และกรอก metadata ให้ครบ |
| 3 สิทธิ์ | ให้น้อยที่สุด อ่านอย่างเดียวถ้างานไม่ต้องเขียน · 1 key ต่อ 1 project |
| 4 วันหมดอายุ | ตั้งทุกครั้งที่ provider ให้ตั้ง · เตือนคุณก่อนหมด 14 วัน |
| 5 การอ่าน | อ่านผ่าน infisical run เท่านั้น ห้ามเปิดไฟล์ key ของเครื่อง |
| 6 การสร้าง | สร้างผ่าน KeyFetch เท่านั้น คุณแค่ login ผ่าน relay และไม่มี AI ตัวไหนเห็นค่า key |
| 7 key หลุด | ติดป้าย leaked → สร้าง key ใหม่ → ใส่ Infisical → เช็คว่าใช้ได้ → ยกเลิกอันเก่า → ไล่ดูว่าใครเห็น |
| 8 การยกเลิก | ยกเลิก key เก่าได้หลังจาก key ใหม่ใช้ได้แล้วเท่านั้น |
| 9 ตัวกัน key หลุด | gitleaks, GitHub secret scanning, hook ใน session, การ์ด Run ที่กรอง key |

| ตัวเลข | ค่า |
|---|---|
| test ของ KeyFetch ที่ผ่าน | 48 จาก 63 บน Contabo (อีก 15 ตัว Node บนเครื่องไม่มี WebSocket ตกเหมือนกันบน main) |
| ตัวกันที่ทำงานครบแล้ว | 5 จาก 8 (อีก 1 ตัวทำงานบางส่วน และอีก 2 ตัวยังไม่ได้ทำหรือปิดอยู่) |
| repo สาธารณะที่ปิด GitHub secret scanning อยู่ | 0 (เปิดแล้วทั้ง Agents-Core และ Agents-Rules 27 ต.ค. 14:5x) |
| งานที่ยังไม่ได้ทำ | 3: ระบบเตือนวันหมดอายุอัตโนมัติ (ระหว่างนี้ C-level จดใน LungNote เอง), gitleaks ก่อน push, hook กันการเปิดไฟล์ /etc/infisical |

- เสร็จแล้ว: เปิด GitHub secret scanning และ push protection ทั้ง 2 repo (ฟรีสำหรับ repo สาธารณะ)
- รอคุณตัดสิน: IRON ข้อ 65 ใหม่ และแก้ IRON ข้อ 34 ข้อย่อย 5 ซึ่งยังเขียนว่าย้าย key เข้า Org-Infra ได้ ขัดกับที่คุณเลือก free plan เมื่อ 26 ต.ค. จะส่งเป็น PR แยกให้คุณดู
