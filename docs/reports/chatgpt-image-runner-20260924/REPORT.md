## What it does

```
<pwvenv python> tools/chatgpt_images.py \
    --brief docs/ops/briefs/<brief>.md --out <output dir> \
    [--dry-run] [--one <name>] [--cdp-url http://127.0.0.1:9224] [--timeout-s 360]

# or --json <list.json> instead of --brief, for [{"name","prompt","attach"?}, ...]
```

Per image not already `"status": "done"` in `<out>/ledger.json`: navigate to
`https://chatgpt.com/` (always opens a fresh chat in this account — no
"New chat" click needed, per REPLAY.md), optionally attach a reference
image, paste the prompt via a synthetic `paste` event, submit, poll for
completion, then fetch the generated image's bytes **straight from the page**
(`page.request.get()` against the `<img>`'s own `oaiusercontent` src) — never
from Downloads, which is shared with other workers and has already handed
one task someone else's file (task-f34224d9). Before saving, its MD5 is
checked against every `*.png` already in the output directory (a fresh scan
every time, not just what the ledger knows about) and refused on a match.
Saved as `<out>/<name>.png`, never overwriting an existing file.

Any of **logged out / usage limit / paywall / a turn that ends with no
image** (refusal, a clarifying question, or anything else this zero-model
runner has no way to judge) **stops the whole run cleanly**: the ledger row
for the image in progress records what was seen (hazard kind + verbatim
excerpt), the process exits 1, and re-running the same command later skips
every name whose ledger status is already `"done"` and retries the rest.
A single image's own technical hiccup (attach failed, the pasted text didn't
verify, a 6-minute timeout, a duplicate MD5, the target file already
exists) fails only that image (`status: "failed"`) and the batch continues
— those aren't money/policy hazards, just something to fix and retry.

## Design choices not fully pinned down by the brief

- **Markdown `ATTACH:` line**: the brief says "optional per image: a
  reference image path to attach" but the only markdown brief on file
  (round3-village) has no reference images, so there was no format to copy.
  Added an optional `ATTACH: <path>` line anywhere in an image's block
  (before `PROMPT START`); untested against a real brief. The JSON format's
  `"attach"` field is the same feature with no format ambiguity.
- **Refusal is a whole-batch stop, not a per-image skip.** The brief's Build
  section lists "refusal" in the same "stop cleanly" sentence as logged
  out/usage limit/paywall. The manual round-3 brief (a human-followed
  brief, not this runner) instead treated a refusal as one line in a table
  and moved on — but that had a person or model reading the refusal each
  time. This runner has nobody watching between images, so it treats an
  ended-with-no-image turn exactly like the other three hazards: stop, log
  the assistant's actual text verbatim, let the CEO/CTO decide whether to
  retry that name. Flagged here since it's a judgement call, not something
  the brief pinned down.
- **`attach_reference()` is UNVERIFIED against the live DOM** — no logged-in
  session was reachable while writing this (see below). It tries
  `input[type="file"]` directly first (works even hidden behind a "+" menu,
  per ordinary Playwright practice), then falls back to opening an attach
  button. Flagged in its own docstring; first live use should confirm or
  correct the selector.
