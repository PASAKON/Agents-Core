## 2. Existing Lock Stores & Structural Flaws

1. **Hub Postgres `locks` Table (`lib/db.py:1360-1440`, `lib/db_pg.py:371`, `lib/router.py:305-333`)**
   - **Implementation**: `acquire_lock(key, owner, ttl=300)` (`lib/db.py:1360-1370`) runs:
     - `SELECT owner, expires_at FROM locks WHERE key=?` (`lib/db.py:1365`)
     - Checks in Python if `row["owner"] != owner and row["expires_at"] > now` (`lib/db.py:1367-1368`)
     - `INSERT OR REPLACE INTO locks(key, owner, expires_at) VALUES(?,?,?)` (`lib/db.py:1369`, rewritten by `lib/db_pg.py:371` to `INSERT ... ON CONFLICT (key) DO UPDATE`).
   - **Flaws**:
     - **TOCTOU Race**: Two callers running `acquire_lock` concurrently both see no row (or an expired row) in `SELECT`, and both execute `INSERT ... ON CONFLICT DO UPDATE`, silently overwriting the first winner (`lib/db.py:1365-1369`). (Note: `lib/router.py:314-322` works around this for `host-router:contabo-cpu` by writing raw SQL `DELETE FROM locks WHERE key=%s AND expires_at < %s` followed by `INSERT ... ON CONFLICT(key) DO NOTHING`.)
     - **No Waiter Queue / No Reactive Wakeup**: `release_lock(key, owner)` (`lib/db.py:1373-1375`) simply deletes the row (`DELETE FROM locks WHERE key=? AND owner=?`) without waking any blocked task.
     - **No Dead-Holder Reaping**: If a worker process dies while holding `proj:<project>:path:<path>` (`tools/delegate.py:2718`, `ttl=3600`), the lock stays held until the 1-hour TTL expires.

2. **Console Browser-Home Lock Store (`Console/src/relay/locks.js:1-107`, `Console/src/relay/routes.js:374-402`, `tools/home_lock.py:1-235`)**
