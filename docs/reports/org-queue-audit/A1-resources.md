## Coordination findings

- Existing locks are not interchangeable. The hub helper performs SELECT then INSERT OR REPLACE (`lib/db.py:1360`); this read/write sequence alone is not evidence of a race-free lease claim. The router exception instead uses INSERT ON CONFLICT DO NOTHING RETURNING (`lib/router.py:320`). Keep their semantics distinct.
- Console browser release removes a holder and returns; the inspected function does not dispatch a waiter (`/opt/MoonieXHQ/Projects/MoonieX/Console/src/relay/locks.js:98`). Host/budget/disk queues are watchdog-drained (`runners/watchdog.py:970`, `runners/watchdog.py:997`, `runners/watchdog.py:1411`). Studio uses a 1500 ms interval (`/opt/MoonieXHQ/Projects/MoonieX/ComfyRunpod/studio/src/lib/queueRunner.ts:108`, `/opt/MoonieXHQ/Projects/MoonieX/ComfyRunpod/studio/src/lib/queueRunner.ts:526`). These are not evidence of one org-wide immediate release-to-waiter handoff.
- Studio's queue lock explicitly assumes one Node process (`/opt/MoonieXHQ/Projects/MoonieX/ComfyRunpod/studio/src/lib/store.ts:220`). Independent batch processes need shared admission even though Studio already has a queue.
- Recommended design implication: acquire browser/screen mutexes and GPU/host pool slots separately from account-wide rate reservations. Credit reservation keys should identify the actual billing account; Seedance-through-fal must debit the same fal budget. This is a proposal, not current behavior.
