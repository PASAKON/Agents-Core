# REPORT task-9b209e15

## Summary

Built the hub schema for Org Mesh W2.1: two new tables, `hosts` (host
registry) and `letters` (cross-host C-level mailbox), hand-synced into both
the SQLite `SCHEMA` (`lib/db.py`) and the Postgres `PG_SCHEMA`
(`lib/db_pg.py`), created idempotently through the existing `init_schema()`
path (`CREATE TABLE IF NOT EXISTS`). Added the read/write functions the
brief specifies for both tables. `seed_hosts_from_config()` writes only
identity fields (os/agents_root/provides/max_workers) and never clobbers
probe fields another writer already set — `upsert_host()` only touches the
columns it's given. `lib.config` stays a lazy import inside
`seed_hosts_from_config()` only; `lib/db.py` is unchanged at module level
and still imports without PyYAML (`tests/test_hook_guard_without_yaml.py`
passes). New test file `tests/test_db_hosts_letters.py` (16 tests, SQLite,
tmp_path) covers every scenario in the brief; added a few offline
`lib.db_pg._translate` sanity tests and one gated Postgres round-trip case.
Full suite: 2854 passed, 4 failed (all four are the exact pre-existing
failures named "known unrelated" in the task brief), 26 skipped.

## Files Changed

- `lib/db.py` — added the `hosts` and `letters` `CREATE TABLE IF NOT EXISTS`
  blocks (+ `idx_letters_to_host_status`) to `SCHEMA`; added
  `_HOST_COLUMNS`, `upsert_host()`, `get_host()`, `list_hosts()`,
  `seed_hosts_from_config()` (lazy `from lib import config`),
  `create_letter()`, `get_letter()`, `pending_letters()`,
  `mark_letter_delivered()`, `record_letter_attempt()`. Nothing above
  `create_task` changed — the module-level "importable without PyYAML"
  contract is untouched.
- `lib/db_pg.py` — mirrored the same two `CREATE TABLE` blocks into
  `PG_SCHEMA`, `letters.id` using `GENERATED BY DEFAULT AS IDENTITY` (same
  pattern as `events`). No changes to `_translate`/`_rewrite_insert_or_replace`
  — `upsert_host`'s SQL is a hand-written `ON CONFLICT(host) DO UPDATE SET
  col=excluded.col`, which is valid Postgres syntax unchanged (same pattern
  already used by `register_cxo_session` in `lib/db.py`), so it never
  touches the `INSERT OR REPLACE` rewriter or its `_UPSERT_PK` table.
  `create_letter`/`record_letter_attempt` use `... RETURNING id` /
  `RETURNING attempts`, which is valid unchanged SQL on both backends (no
  `lastrowid` on psycopg cursors, so this is the cross-backend way to read
  back an autoincremented id).
- `tests/test_db_hosts_letters.py` (new) — 16 tests on a tmp_path SQLite
  ledger: init-on-existing-ledger adds both tables + leaves `tasks` rows
  intact; hosts CRUD + column-allowlist rejection; `seed_hosts_from_config`
  creates one row per host and is idempotent while keeping probe fields
  (both via `monkeypatch.setattr(lib.config, "hosts", ...)`, not a
  `sys.modules` swap — `from lib import config` inside the function resolves
  through the already-imported `lib` package attribute, which a
  `sys.modules` patch alone would not intercept); a source-level assertion
  that the lazy import lives inside `seed_hosts_from_config` and nowhere
  above `create_task`; letter lifecycle (create → pending → delivered,
  second `mark_letter_delivered` returns `False`); `pending_letters` scoped
  per host; 5 failed attempts flips `status` to `failed`; a missing-id call
  to `record_letter_attempt`/`mark_letter_delivered` is a safe no-op/`False`.
- `tests/test_db_pg_translate.py` — 3 new offline tests proving the
  `upsert_host` ON CONFLICT SQL, the `create_letter` RETURNING SQL, and the
  `record_letter_attempt` RETURNING SQL all pass through `_translate`
  cleanly (placeholder translation only, no crash, no unwanted rewrite).
- `tests/test_db_backend_pg.py` — added `hosts`/`letters` to `_TABLES` (so
  the fixture's drop/recreate cycle covers them) and one gated
  `test_hosts_and_letters_roundtrip_on_postgres` (skipped without
  `ORG_TEST_DB_URL`, same as every other test in this file).

## Notes for Reviewer

- `upsert_host()` deliberately does NOT validate `status`/`hosts.provides`
  contents against the enum values the brief lists
  (`online/offline/pending_identity/left`) — the brief specifies the values
  as documentation, not as an enforced `VALID_STATUS`-style check like
  `tasks.status` has, and later waves (node_agent, W2.3) own writing that
  value. Flag if you want an enum guard added now instead.
- `record_letter_attempt` and `mark_letter_delivered` on a nonexistent
  `letter_id` are silent no-ops (`None` / `False`) rather than raising —
  matches this file's existing convention for `get_task`/`update_status`
  (nonexistent ids don't raise), not a new pattern.
- Did not touch `scripts/migrate_tasks_db.py` or
  `scripts/hub/export_to_sqlite.py` per the brief's explicit "stay inside
  the listed files" — confirmed via `grep` that neither file references
  `hosts`/`letters` before or after this change.
- `hq_root` is a `hosts` column but is NOT written by
  `seed_hosts_from_config()` — the brief's own field list for that function
  is "os, agents_root, provides, max_workers" only; `hq_root` is left for
  whatever later wave populates it (node_agent identity, C1).
