## The page, and why the stock flags do not work as-is

1. **The account page shows the current token in full, unmasked, on every load** (text of
   `p.chakra-text.css-1una8gt` in the "Account Details" card; `script#__NEXT_DATA__` may hold it too). A new
   signup already has one. Do not scan the page with anything that prints text: redact token-shaped strings
   in code first, never read `input.value`, report holders by CSS path only.
2. **"Generate new API key" is the create step, and it is instant**: an icon button with `aria-label="Generate new
   API key"` (next to `aria-label="Copy API key"`). No confirm dialog: the click fires the request at once and
   the page re-renders with the new token. The page only ever shows one token, so the old one is taken to be
   replaced (inferred, not tested: no old value was ever held to try).
3. **`capture_key.mjs --click` cannot find it**: `FIND` matches a button's `innerText`, and both icon buttons are
   empty (`--click '^$'` matches 4). So `--check` cannot pass on this page. Workaround that keeps the capture
   zero-model: run `capture_key.mjs --wait` (it listens, does not click), then click by aria-label from a second
   CDP client that refuses unless exactly one visible button matches.
4. **Page mode (`--dom`) is wrong here**: the element already shows the OLD token, so the read loop would
   capture it before the new one paints. Use wire mode.
5. After the login a Chrome intercept tab `chrome://signin-dice-web-intercept.top-chrome/` appears; `--tab
   'pixellab\.ai/account'` skips it.

## Capture (replay)

```bash
cd /opt/MoonieXHQ/Agents/Core            # Contabo; the tab must be on https://www.pixellab.ai/account
LOG=$(mktemp)
node scripts/keyfetch/capture_key.mjs http://127.0.0.1:9288 \
  --tab 'pixellab\.ai/account' \
  --project MoonieX-Bedrock --env prod --as setup \
  --name PIXELLAB_API_KEY \
  --match 'api\.pixellab\.ai/generate-new-token(\?|$)' --field token \
  --wait --new-only \
  --comment '<purpose, one sentence>' \
  --meta 'provider_name=none (no name field)' \
  --meta 'console_url=https://www.pixellab.ai/account' \
  --meta 'scope=account-wide: PixelLab offers one API token per account; regenerate replaces it' \
  --meta 'wide=yes' --meta 'why_wide=PixelLab offers one account token' \
  --meta 'expires=<rotate-by YYYY-MM-DD>' --meta 'owner=CTO' \
  --meta 'created=<YYYY-MM-DD> <sid>' --meta 'spend_cap=<what the page offers, or none>' \
  >>"$LOG" 2>&1 &
CAP=$!
for i in $(seq 1 60); do grep -q 'armed; waiting' "$LOG" && break; sleep 0.5; done
grep -q 'armed; waiting' "$LOG" && node --input-type=module -e '
  const t = (await (await fetch("http://127.0.0.1:9288/json/list")).json()).find(t => t.type === "page" && /pixellab\.ai\/account/.test(t.url));
  const ws = new WebSocket(t.webSocketDebuggerUrl); await new Promise(r => ws.onopen = r);
  ws.send(JSON.stringify({ id: 1, method: "Runtime.evaluate", params: { returnByValue: true, expression:
    `(() => { const b = [...document.querySelectorAll("button")].filter(b => b.getClientRects().length && b.getAttribute("aria-label") === "Generate new API key"); if (b.length !== 1) return b.length; b[0].click(); return 1; })()` } }));
  const m = await new Promise(r => ws.onmessage = e => r(JSON.parse(e.data)));
  console.log("matching buttons:", m.result.result.value); ws.close();'
wait $CAP; echo "capture exit=$?"; cat "$LOG"; rm -f "$LOG"
```

Output of the first run: `--new-only: PIXELLAB_API_KEY absent`, `armed`, `provider answered HTTP 200;
PIXELLAB_API_KEY: present`, `dialogs still open: 0`, one `created …` line from `put`, `saved 1/1`, exit 0.

- **Rotation** is the same command without `--new-only` (the `put` becomes an update). Expect the click to end
  the old token, so restart every consumer right after it. PLAN §2's rotate-forward rule cannot be kept here:
  PixelLab offers no second token to overlap with.
- Exit 7 after HTTP 200: the new token exists at PixelLab and is not in Infisical, and the old one has likely
  been replaced. Fix the flags and rerun at once: the rerun replaces the lost token.
- `--new-only` refuses before anything is armed when the secret already exists.
