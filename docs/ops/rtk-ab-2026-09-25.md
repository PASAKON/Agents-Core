# RTK org-wide adoption A/B — 2026-09-25 (task-9ea68924)

## Question

Should MoonieX HQ wire [rtk-ai/rtk](https://github.com/rtk-ai/rtk) v0.50.0 (a
PreToolUse hook that rewrites recognized Bash commands to compact-output
wrappers) into every project org-wide?

## Decision rule (CEO-approved plan 2026-09-25)

**ADOPT** if arm B (RTK) uses **≤ 0.8×** arm A's total tokens (cache read +
cache write + fresh input + output, deduped by `message.id`) with **equal
graded correctness** (10/10 on the same answer key) on **≥ 2 of 3** paired
runs. Otherwise **DO NOT ADOPT**.

## Method

- **Fixture:** `mooniex-agents` at commit `472466a9` (this task's branch base
  = `origin/main` at kickoff), checked out twice via `git worktree add
  --detach` into `tools/rtk_ab/arms/{A,B}` (gitignored), sparse-checked-out
  (cone mode) to `tools scripts tests lib .claude` — a full checkout is
  916 MB (tracked-blob sum), sparse is ~11 MB per arm. `.claude/` (tracked:
  `settings.json` + 5 project PreToolUse hooks + `skills/`) is kept in **both**
  arms so the org's existing hooks apply identically; the only difference
  between A and B is arm B's own `.claude/settings.local.json` (below).
- **Job:** `tools/rtk_ab/PROMPT.md` — 10 read-only questions (pytest counts on
  `tests/test_restore_scripts.py`, a `skill(`-prefix count over `git log
  --oneline -30`, the 5 largest files under `tools/`, `.py` counts under
  `scripts/`/`lib/`, `def main(`/`import argparse` grep counts under
  `tools/`, an `ls -R scripts` directory-header count, a `git show --stat
  HEAD` fact, `wc -l tools/token_profile.py`) — deliberately mixed simple
  commands (`git log`, `git show`, `wc -l`) RTK recognizes and compound/piped
  ones (`find … | wc -l`, `grep -l … | wc -l`, `ls -R … | grep -c`) it
  doesn't, per the survey's prediction that most of this org's real Bash is
  exactly the latter. Answers computed by hand with plain shell into
  `ANSWER_KEY.json` before any run; `grade.py` scores a run's final JSON line
  against it, out of 10.
- **Runs:** `tools/rtk_ab/run_ab.py`, `claude -p "<PROMPT>" --model
  claude-sonnet-5 --output-format json --permission-mode bypassPermissions`,
  cwd = the arm dir, 20 min timeout. 1 smoke run per arm first, then 3 paired
  measured runs alternating start order (i=1 A,B · i=2 B,A · i=3 A,B) — 8
  headless calls total (budget cap).
- **Measurement:** per run, `tools/token_profile.py`'s `scan()` against the
  run's transcript `~/.claude/projects/<slug>/<session_id>.jsonl` — tokens by
  class deduped by `message.id` (a raw sum overcounts ~2×), plus turns and
  Bash tool-result chars from the same scan.

## Hook wiring that worked

`rtk init` (no `-g`) for Claude Code only writes `CLAUDE.md` prose + a filter
template — no hook. RTK's real interception is documented as `rtk init -g`
only (writes `~/.claude/settings.json`), which is forbidden here (never touch
global settings). Claude Code's hook schema doesn't care who writes it, so
this JSON was hand-verified against `rtk hook claude`'s real stdin/stdout
contract and placed in **arm B's own** `.claude/settings.local.json` only:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "/Users/gob/MoonieXHQ/Agents/Core/worktrees/mooniex-agents__developer__task-9ea68924/tools/rtk_ab/bin/rtk hook claude"
          }
        ]
      }
    ]
  }
}
```

Verified: piping a simulated PreToolUse payload for `git log --oneline -30`
into `rtk hook claude` returns clean JSON on stdout —
`{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecisionReason":"RTK auto-rewrite","updatedInput":{"command":"rtk git log --oneline -30", ...}}}`
— and an unrecognized/compound command (`python -m pytest ...`, any piped
command) returns **empty stdout**, Claude Code's "no change" convention.

## Install

```bash
gh release download v0.50.0 --repo rtk-ai/rtk \
  --pattern 'rtk-aarch64-apple-darwin.tar.gz' --pattern 'checksums.txt' --dir /tmp/rtk_dl
shasum -a 256 /tmp/rtk_dl/rtk-aarch64-apple-darwin.tar.gz   # matched checksums.txt
tar -xzf /tmp/rtk_dl/rtk-aarch64-apple-darwin.tar.gz -C /tmp/rtk_dl
cp /tmp/rtk_dl/rtk tools/rtk_ab/bin/rtk && chmod +x tools/rtk_ab/bin/rtk
tools/rtk_ab/bin/rtk --version   # rtk 0.50.0
```

`brew install rtk` (homebrew-core, stable 0.50.0) is a legitimate fallback —
not used here, to avoid a global brew-state change for an experiment.

## Bug found by the smoke run

RTK's rewrite emits the bare literal `rtk` as argv[0] (not its own install
path). `tools/rtk_ab/bin` isn't on the default `PATH`, so **every** rewritten
command in the first B smoke run failed `exit 127: command not found: rtk`.
The tested agent never saw an RTK-shaped error — just commands that
mysteriously failed — and burned many extra turns working around it: it
fell back to `/bin/ls` with an absolute path, `cat`'d `.git` three times,
tried 5 separate ways to get `wc -l tools/token_profile.py` to work (four
failed silently with exit 127 before one redirect form happened to dodge the
rewrite). Net effect: the broken smoke run for B used **more** than double
A's tokens (3.92M vs 1.76M) and 42 turns vs 20 — the opposite of RTK's
purpose, purely from a missing `PATH` entry. **Fix** (before any measured
run): `run_ab.py` prepends `tools/rtk_ab/bin` to the child `claude` process's
`PATH` (a no-op for arm A). Mirrors RTK's own README: "Installs to
`~/.local/bin`. Add to PATH if needed." **The smoke runs are excluded from
the decision table below** — they're a pre-flight check, and B's smoke number
in particular reflects the PATH bug, not RTK's real behavior.
