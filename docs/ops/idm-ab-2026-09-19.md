# IDM A/B — the whole corpus against 51k frames, 2026-09-19

Both models scored on **identical frames in one process**: 7 held-out val shards
(118k frames, takes never seen in training) plus 3,277 registered YouTube frames.

| | A — baseline | B — full corpus |
|---|---|---|
| train frames | 51,198 | 681,086 |
| epochs | 6 | 2 |
| where | Contabo CPU, 55 min | Contabo CPU, 205 min |

## The headline

**B wins on every accuracy measure, for both classes, and on every timing
measure except one that did not move.** There is no dimension measured here
where more data made the model worse.

## JUMP — 13,640 onsets

| | A | B | Δ |
|---|---|---|---|
| precision | 0.470 | **0.522** | +0.052 |
| recall | 0.918 | **0.933** | +0.014 |
| F1 | 0.622 | **0.669** | +0.048 |
| on time (exact frame) | 93.54% | **94.92%** | +1.38 |
| within 1 frame | 98.33% | **99.35%** | +1.02 |
| early | 4.41% | **3.01%** | −1.40 |
| late | 2.05% | 2.07% | +0.02 |

The precision gain is the real one: recall was already 0.92, so the old model
was finding the presses and inventing extra ones. B invents fewer.

The timing split says **the fix landed on early presses, not late ones** —
early fell by a third while late did not move at all. Worth knowing before
anyone tunes a threshold to chase timing: there is no late problem to chase.

## SLIDE — 1,146 onsets, and the biggest winner

| | A | B | Δ |
|---|---|---|---|
| precision | 0.310 | **0.378** | +0.068 |
| recall | 0.732 | **0.806** | +0.074 |
| F1 | 0.435 | **0.515** | +0.079 |
| on time | 79.08% | **86.11%** | **+7.03** |
| early | 12.72% | **7.64%** | −5.08 |
| late | 8.20% | **6.24%** | −1.96 |

Slide improved more than jump on every single measure. That is the expected
shape and the reason this split exists: slide is **1.20%** of frames against
jump's 10.73%, so it was the class starved of examples, and it is the class
that 13× more data helped most. A headline F1 would have reported this as one
modest number and hidden which half moved.

Slide remains much weaker than jump in absolute terms (F1 0.515 vs 0.669). If
anything gets attention next, it is slide.

## YOUTUBE — 3,277 frames, no labels

Nobody logged a stranger's key presses, so accuracy is unmeasurable here. What
is measurable is the thing that actually failed before: whether the model is
still **willing to be sure** on footage from another capture pipeline.

| | A | B | Δ |
|---|---|---|---|
| mean | 0.242 | 0.252 | +0.011 |
| p90 | 0.646 | **0.768** | +0.122 |
| over 0.7 | 7.38% | **13.03%** | +5.65 |
| over 0.9 | 1.46% | **4.30%** | +2.84 |

Nearly 3× as many frames the model will commit to. The collapse-to-the-middle
failure that sank the first Gate 2 attempt is further away, not closer.

## What this does NOT say

**These YouTube numbers are not comparable to the 8.21% over-0.9 reported on
2026-09-18.** That figure came from a model whose weights were never saved
(`--out` is optional on the old trainer and was never passed), so it cannot be
re-scored on these frames, and this run's baseline reaches only 1.46% on the
same metric. Treat 8.21% as unreproducible rather than as a number B failed to
beat. The comparison above is valid because both arms here ran in one process
on one frame set; any comparison to the older figure is not.

The reconstructed baseline is otherwise faithful: its in-domain precision,
0.470, sits inside the 0.433–0.479 band the original gate runs reported, which
is the reason it is usable as a control at all.
