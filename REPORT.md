### `scripts/hook-self-repo-guard.py` — fail-open design

The task requires this hook and `hook-log-prompt.py` to get a 3s timeout
and **fail OPEN** on a slow/unreachable hub, while keeping the hook's
original **fail-CLOSED** protection semantics for every case where the hub
*did* answer. Those are opposite defaults, so `load_touches()` now
distinguishes two failure modes:

- Connection to the registry never succeeded AND `ORG_DB_URL` is set →
  raises `HubUnreachable`. `decide()` catches this specifically, prints one
  stderr line, and returns `(0, "")` (allow).
- Anything else (DB missing under SQLite, corrupt file, no task row, bad
  JSON) → raises `GuardError` exactly as before → refuse, unchanged.

`db_path_for(root)` (the DEV worktree's own checkout root, not this
process's `ORG_ROOT`) is passed through to `get_conn(path=..., readonly=
True, timeout=3)` — under SQLite this addresses the same file the hook
always addressed (and is what lets `scripts/test_self_repo_guard.py`'s
fixture-injected `tmp_path` checkouts keep working); under Postgres `path`
is ignored, since `ORG_DB_URL` names one global registry.

Demonstrated (`ORG_DB_URL` pointed at a closed port, hook run by hand):

```
$ ORG_DB_URL='postgresql://postgres@127.0.0.1:1/nope' .venv/bin/python3 -c "
import importlib.util
spec = importlib.util.spec_from_file_location('guard', 'scripts/hook-self-repo-guard.py')
guard = importlib.util.module_from_spec(spec); spec.loader.exec_module(guard)
event = {'tool_name': 'Edit', 'tool_input': {'file_path': 'lib/db.py'}}
print(guard.decide(event, cwd='<repo>'))
"
[self_repo_guard] hub unreachable within 3.0s, failing OPEN (allow): ORG_DB_URL points at 127.0.0.1:1 but it is unreachable: connection failed: connection to server at "127.0.0.1", port 1 failed: could not receive data from server: Connection refused
CODE: 0 MSG: ''
# real elapsed: 0.19s
```

Same demonstration for `hook-log-prompt.py`'s `_task_owners()` — returns
`{}` (its existing "no filtering data" behaviour) in 2ms with a stderr
line, instead of hanging on the connection attempt.

## LIKE / case-sensitivity audit

Postgres `LIKE` is case-sensitive; SQLite's is ASCII case-insensitive by
default.

- **`lib/db.py`** (2 sites: the `report LIKE 'path collision with%'` OR-chain
  in `init()`'s backfill, and `release_task_locks`'s `key LIKE
  'proj:...:path:%'`) — both compare against literal ASCII prefixes this
  codebase itself generates in a fixed case. No change; plain `LIKE` is
  correct (and on Postgres, actually *more* correct than SQLite's default
  — a lock key derived from a mixed-case file path must stay
  case-sensitive).
- **4 files doing a human-typed short-id lookup** where SQLite's
  case-insensitivity was genuinely relied on (`tools/send_to_worker.py`,
  `tools/remote_worker_log.py`, `tools/inject_prompt.py`,
  `tools/cto_chat_designer.py`) — **NOT FIXED, see Blockers.** The fix
  (already worked out, not applied) is `UPPER(id) LIKE UPPER(?)`, not a
  literal `ILIKE` — `ILIKE` is Postgres-only syntax and would break the
  SQLite backend outright.
- **2 files doing a lock-key/`owner_cto` prefix match**
  (`tools/session_reconcile.py`, `tools/gc_stale_tasks.py`) — same
  reasoning as `lib/db.py`: case-sensitive is correct, no change needed.

### Local Postgres 16 setup used (repeatable on Contabo's `org_test`)

```bash
brew install postgresql@16      # binaries under /opt/homebrew/opt/postgresql@16/bin

export PATH="/opt/homebrew/opt/postgresql@16/bin:$PATH"
PGDATA=<scratch dir>             # NOT under a long worktree path -- macOS caps
                                  # unix-socket paths at 103 bytes; initdb succeeds
                                  # into a long PGDATA but the server then fails to
                                  # bind its socket there
initdb -D "$PGDATA" -U postgres -A trust --locale=en_US.UTF-8 -E UTF-8

mkdir -p /tmp/org_test_pgsock    # short socket dir, works regardless of PGDATA length
pg_ctl -D "$PGDATA" -o "-p 54329 -k /tmp/org_test_pgsock" -l "$PGDATA/log" start

createdb -h /tmp/org_test_pgsock -p 54329 -U postgres org_test

# stop when done:
pg_ctl -D "$PGDATA" stop -m fast
```

`ORG_TEST_DB_URL=postgresql://postgres@127.0.0.1:54329/org_test` (TCP, not
the socket — psycopg's default URL parsing wants host:port).
